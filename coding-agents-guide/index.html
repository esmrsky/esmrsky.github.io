🗺️ Map of the landscape

Anthropic

Claude Code

Agentic coding app (Desktop + CLI). Models: Sonnet 5, Opus 5, Fable 5.

Memory: CLAUDE.md · Plan mode · Subagents · Worktrees · Skills/hooks · /goal /compact

OpenAI

Codex

Agentic coding in CLI, IDE, app (merged with ChatGPT Work). Models: GPT-5.6 Sol / Terra / Luna.

Memory: AGENTS.md · Effort ladder + Ultra · Goals · Parallel agents

Both tools solved “can write code.” The game now is routing (which model/effort), verification (does it actually work), and orchestration (parallel sessions, skills, long runs) — not more magic prompts.

📌 From Boris Cherny, Anthropic & recent practitioner tips

Sourced from Boris’s YC Startup School 2026 talk (day after Opus 5), his public threads, Anthropic docs, and high-signal X/Reddit for website work. Left out advice that only applied to weaker models.

✅ 1. Verification is the #1 lever (2–3× quality)

Claude stops when the work looks done. Without a pass/fail check, you become the verification loop. Give it something it can run itself.

For websites: local preview, Chrome/DevTools, screenshots of key breakpoints, visual compare to a reference, Lighthouse, “don’t stop until the hero matches this brief on mobile and desktop.” Write success criteria into the prompt.

Boris (YC): verification is “probably the single most important thing that people do not get right.”

🗑️ 2. Press delete every ~6 months

From the YC talk, almost verbatim: every six months, delete your CLAUDE.md, skills, and hooks. See what the model does without them. Re-add only what still fails repeatedly.

Anthropic did this internally for Opus 5 / Fable 5 — ablation deleted ~80% of Claude Code’s system prompt with no eval loss. Old instructions written for weaker models often hobble stronger ones.

Practical size target: ~150–200 lines. Put only what Claude cannot infer from the code.

🔥 3. Harder problems + short prompts — let it cook

Stop march-order prompts (“do 1, then 2, then 3”). Describe destination, guardrails, and exit criteria. Give a task that feels slightly too hard, then step back.

Boris’s YC example: a ~3-sentence job that ran 14–15 days — rewrite Electron app in Swift, run both in a Mac VM, screenshot, pixel-compare, don’t stop until done.

For sites: “Ship a one-page brand site that matches this reference on mobile/desktop; open the preview and iterate until hero and type scale match.” Not a 20-step script.

🌳 4. Parallel sessions / worktrees (still the biggest unlock)

Boris’s long-standing #1 productivity tip — still what practitioners repeat: 3–5 isolated Claudes (git worktrees or Desktop sessions). One homepage direction, one secondary page, one responsive pass — clean context each.

claude --worktree feature-hero
claude --worktree page-about
claude --worktree responsive-pass

One coherent goal per session; don’t stuff three client tasks into one chat.

📝 5. CLAUDE.md as mistake log + /init, then prune

After every correction: “Update CLAUDE.md so you don’t make that mistake again.” Run /init for a first draft, then cut hard. Nested CLAUDE.md files beat one giant root file.

⚙️ 6. Skills / commands for anything you do daily

If it happens more than once a day (a11y pass, OG check, brand type scale, deploy checklist), make a skill or slash command and commit it. Subagents for research/verify keep the main window clean.

🧹 7. Fresh session per coherent task

Long messy threads degrade. Pattern that keeps showing up on X/Reddit: one goal → one session → /clear or new session when the goal changes. Use /compact with focus instructions mid-session.

Unhobbling, not more instructions. Product overhang = capability the model already has that your setup isn’t eliciting. Hobbling = your prompts/config getting in the way. With v5 models the default move is fewer crutches, harder tasks, and a verification loop — not a thicker CLAUDE.md.

What not to cargo-cult: “Always start in plan mode” and “always use the strongest model for everything” were truer on older models. Boris has moved toward more auto mode and less mandatory planning on strong models.

🧰 Nick Saraev-style field tips & practitioners

Durable habits from Nick Saraev’s Claude Code courses and other practitioners. No recent Claude-5-only masterclass from Nick — these pieces still hold for website / client work.

🗂️ 1. Separate client vs personal workspaces

One client’s brand rules should not bleed into another. Separate folders, sessions, and project-local CLAUDE.md / CLAUDE.local.md. Agency rule: one session = one client goal.

🌐 2. Browser / DevTools verification as default for UI

For marketing sites, “tests pass” is not enough. Open local preview, screenshot breakpoints, or drive Chrome/DevTools MCP until hero, type, and mobile match the brief. Put this loop in a skill.

📎 3. Verification lives in skills — not a fat root memory file

Progressive disclosure: root memory stays lean (stack, gotchas, pointers). Detailed verify steps, a11y, OG, brand-scale rules live in skills that load when needed.

📖 4. Docs-first for unfamiliar APIs

Forms, analytics, CMS, payments: tell the agent to read official docs before inventing integration code. Cuts confident-but-wrong API usage.

🧾 5. Mistakes → memory file; daily workflows → skills

Same loop as Boris’s points 5–6: permanent rules go in memory; anything you repeat daily becomes a skill — don’t re-explain brand or deploy steps in chat.

⌨️ Claude Code Desktop — Slash commands

How this is organized: Highest-ROI commands first, then autonomous work (/goal, /loop), then the rest. /plan is situational (multi-file / risky changes) — not mandatory for every task on strong models. Model and effort switches live in the Desktop UI, so those slash commands are marked skip. Type / in the input to see what your current version supports.

⭐ Highest ROI (use these)

/compact [instructions] High value

Summarizes the conversation history and frees context while trying to keep the important parts.

When: Usage indicator is climbing (roughly 50–70%), or right after finishing a clear chunk of work before starting the next phase.

Why it matters: Long sessions re-send a lot of history every turn. Still the single best way to stay efficient in Desktop.

Tip: Always give focus instructions. A bare /compact is weaker.

/compact keep the current plan, the files we’ve been editing, and any unresolved errors
/compact focus on the auth refactor and the remaining test failures
/clear High value

Starts a completely fresh conversation. The previous one stays available in the session sidebar.

When: Switching to a completely unrelated task.

Why: Leaving multiple unrelated jobs in one session burns tokens and degrades quality.

/plan [description] Useful

Enters plan mode (read-only analysis) before making changes. You can pass a description to start immediately.

When: Multi-file change, refactor, or anything where jumping straight into edits is risky.

/plan fix the auth bug without changing the public API

🔁 Letting Claude keep working (/goal vs /loop)

These two are different tools. Use the right one.

/goal/loop
Next turn starts whenPrevious turn finishesA time interval elapses
Stops whenCondition is met (checked by a small evaluator model)You stop it, or Claude decides the work is done
Best forGetting something finished (tests pass, build succeeds)Polling / monitoring (CI, deploy, PR comments)
/goal [condition] Useful

Sets a completion condition. Claude keeps working across turns until a separate evaluator model confirms the condition is true. One goal active per session.

When: Clear, checkable finish line and you don’t want to keep typing “keep going.”

Tip: Make the condition measurable. Add a turn cap if you want a safety limit.

/goal all tests in test/auth pass and the lint step is clean
/goal npm test exits 0 and git status is clean, or stop after 15 turns
/goal clear

Status: Type /goal with no argument to see current goal, turns, and tokens used.

/loop [interval] [prompt] Useful

Re-runs a prompt on a schedule while the session stays open. Omit the interval and Claude self-paces.

When: Periodic checks (deploy status, CI, open PRs) rather than continuous work until a condition is met.

/loop 5m check if the deploy finished and report any failures
/loop 10m check my open PRs and address review comments
Note: /loop runs on your machine while the session is open. For longer-lived recurring work, Desktop also has Scheduled tasks in the sidebar.
/batch <instruction> Situational

Researches the codebase, breaks a large change into independent units, then (after you approve) runs them in parallel using isolated git worktrees.

When: Big refactors or migrations that can be split. Overkill for small tasks.

/batch migrate the remaining components from pages/ to the new app router

🔍 Review and recovery

/code-review [level] [--fix]Useful

Reviews the current diff for bugs and cleanups. Can auto-apply with --fix.

When: Before accepting a larger set of changes.

/diffUseful

Shows recent / uncommitted changes and per-turn diffs.

/rewindUseful

Rolls back conversation and/or code to an earlier point.

When: Claude went down a bad path and you want a clean undo.

/branch · /fork · /resumeSituational

/branch forks the conversation for experiments. /fork can send work to a background session. /resume returns to a previous session.

📦 A simple practical stack

You don’t need all of the above. For most Desktop users this is enough:

1. /compact with instructions when the usage bar rises

2. /clear (or new session) when switching tasks

3. /plan before bigger changes

4. /goal when you have a clear finish line

5. /loop only when you need periodic checks

Everything else is optional. Highest consistent ROI remains /compact.

Commands and availability can change between versions — type / or /help for the live list.

✅ Still compounds in 2026

These are the same principles across Claude Code and Codex. Detail lives in the Boris / field sections above — this is the short cross-stack checklist.

  • Verification loops — tests, preview, screenshots; agent stops when it looks done unless you give a gate
  • Lean memory as a mistake log — CLAUDE.md / AGENTS.md for gotchas only (~150–200 lines); procedures → skills
  • Outcome + exit criteria — destination and done-ness, not step lists
  • Parallel isolation — worktrees / sessions / Ultra only when work partitions
  • Phase routing — judgment model → volume model; escalate on failed gates only
  • Skills for daily repetition — progressive disclosure over fat system prompts
  • Periodic delete — every ~6 months, drop config that assumed weaker models

🌫️ Fading / often irrelevant now

Always use the strongest model at max effort

Was more true when mid-tier models were weak. Today it burns quota, slows iteration, and adds overthinking on UI polish. Escalate on evidence.

Mandatory plan mode for every task

Critical for ambiguous creative work; optional for “add this card component.” Boris publicly moved toward more auto mode on strong models.

Huge CLAUDE.md / AGENTS.md as a wiki

Models load judgment better; giant instruction piles dilute signal. Keep gotchas; move procedures to skills.

Step-by-step “do 1 then 2 then 3” prompts

Legacy of weaker models. Prefer goal, constraints, verification. Let the agent choose the path.

Prompt-engineering folklore as the main skill

Waves of “prompt eng” → “context eng” age fast. Durable skills: hard tasks, verification design, routing, taste, orchestration.

One endless mega-session

Context rot is real. Fresh session per coherent goal; compact with instructions mid-flight.

🔄 Website workflows that work on both

Claude Code — brand / marketing sites

Direction: Opus 5 high or Extra · 2–3 aesthetic directions + IA + exit criteria.

Build: Sonnet 5 high for sections, components, mobile.

Polish: Opus again if consistency or taste still slips.

Fable: only when Opus still fails after a focused attempt + compact.

Codex — same job, GPT-5.6

Direction: Sol Medium–High.

Build: Terra Medium (Luna for pure volume).

Hard QA: Sol High + visual gates.

Ultra: only when pages/components are independent workstreams.

Shared pattern (copy this)

1. Write definition of done (mobile + desktop, which sections, brand constraints)
2. Judgment model plans / proposes directions
3. Approve or narrow
4. Volume model implements
5. Verify in browser (screenshots / preview) — not “looks done”
6. Escalate model or effort only if the gate fails
7. Log permanent mistakes into CLAUDE.md / AGENTS.md

Quick routing by website task

TaskClaude CodeCodex

Bulk variants, mechanical mobile, transformsSonnet Low–MediumLuna Low–Medium

Independent pages in parallelWorktrees / multi-sessionUltra or multi-session

Escalate only when the acceptance gate fails — not because a stronger model “might” be better.

Client agency hygiene

Separate sessions (or repos) per client so brand rules don’t bleed. Project-local memory files. Browser verification as default for UI — not optional.

📅 Timeline & forecast

2024 – early 2025
Autocomplete → chat coding

Prompt craft mattered a lot. Models needed heavy guardrails and step lists. “Vibe coding” emerges.

Mid 2025 – early 2026
Agentic coding tools go mainstream

Claude Code & Codex mature. Plan mode, memory files, worktrees, long runs. Teams learn verification and parallel sessions.

Now — mid/late 2026
Tiered models + less scaffolding

Claude 5 + GPT-5.6 Sol/Terra/Luna. Labs delete large chunks of system prompts. Coding is “largely solved” for well-specified work; bottleneck shifts to taste, product judgment, orchestration, and trust (review, security, verification).

Next 6–12 months
Longer autonomy + multi-agent default

Directional forecast: multi-day runs become more routine; multi-agent more native; IDE/cloud loops tighter. Config written for weaker models will keep rotting — schedule deletes.

12–24 months
Orchestrator role solidifies

Likely edge: specifying outcomes, designing verification, routing fleets of agents, holding the quality bar, and owning product/brand decisions models still approximate poorly. Treat as a bet, not a guarantee.

🧠 Skills to develop (and de-emphasize)

Invest here

  • Specification & acceptance criteria — clear done-ness
  • Verification design — tests, visual gates, browser loops
  • Model routing — tier + effort by task shape
  • Orchestration — parallel sessions, skills, long goals
  • Taste & brand judgment — especially for client sites
  • Repo legibility for agents — lean memory files, good structure
  • Review discipline — same bar for AI code as human code
  • Config hygiene — periodic delete & rebuild

De-emphasize

  • Memorizing brittle prompt templates
  • Hoarding ever-longer system prompts
  • Hand-typing every line “to stay sharp” as the main skill
  • Tool tribalism (only Claude / only Codex)
  • Assuming last year’s best practice still applies after a frontier jump

For website / agency work specifically: double down on visual verification, client isolation, design-system tokens as source of truth, and phase routing (judgment model → volume model). That’s where quality and margin live.

🎯 Decision cheat sheet

Ambiguous design / architecture / hard bug?
Claude: Opus 5 (Fable if still stuck) · Codex: Sol

Implement locked design, volume revisions?
Claude: Sonnet 5 · Codex: Terra (Luna for pure bulk)

Always attach: definition of done + verification

Escalate: only when the gate fails — not because the model “might be smarter”

Parallelize: isolated sessions / worktrees / Ultra-with-partitions

After mistakes: write the rule into CLAUDE.md or AGENTS.md

Every ~6 months: press delete on bloated config; see what the new models need

One line: Stronger models need fewer crutches, clearer goals, and better verification — not thicker prompts and permanent max effort.
