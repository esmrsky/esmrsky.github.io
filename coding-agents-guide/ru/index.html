🗺️ Карта ландшафта

Anthropic

Claude Code

Агентное приложение для кода (Desktop + CLI). Модели: Sonnet 5, Opus 5, Fable 5.

Память: CLAUDE.md · Plan mode · Сабагенты · Worktrees · Skills/hooks · /goal /compact

OpenAI

Codex

Агентное программирование в CLI, IDE и приложении (объединено с ChatGPT Work). Модели: GPT-5.6 Sol / Terra / Luna.

Память: AGENTS.md · Лестница усилий + Ultra · Goals · Параллельные агенты

Оба инструмента уже решили задачу «уметь писать код». Теперь игра в другом: маршрутизация (какая модель и какой уровень усилий), проверка (работает ли это на самом деле) и оркестрация (параллельные сессии, скиллы, долгие прогоны) — а не новые волшебные промпты.

🟣 Модели Claude 5 Claude Code

Исполнение

Sonnet 5

Быстрый универсал · объём

Сборка секций и компонентов, адаптивные проходы, много правок, рабочие сабагенты.

Суждение

Opus 5

Эксперт на каждый день · практический потолок

Архитектура, дизайн-направление, сложные баги, финальная согласованность. «Умный» выбор по умолчанию для большей части работы над сайтом.

Фронтир

Fable 5

Длинный горизонт · самые сложные 5–10%

Переходи на неё, когда Opus всё ещё промахивается по вкусу или в долгих автономных прогонах. Сильно съедает квоту — не выбор по умолчанию.

Привычки в Claude Code, которые всё ещё окупаются: компактный CLAUDE.md как журнал ошибок · «нажми удалить» примерно раз в 6 месяцев · проверка (превью/скриншоты) · параллельные worktrees · результат + критерии готовности, а не списки шагов · /compact с указаниями, на чём сфокусироваться.

🔵 Модели GPT-5.6 Codex

Флагман

Sol

API ~$5/$30 на июльском запуске (проверь актуальные) · самая глубокая агентность

Неоднозначная работа по многим файлам, сложная диагностика, ответственное ревью, длинные цепочки инструментов. Сильные результаты в терминальных и агентных бенчмарках.

Баланс

Terra

API ~$2.50/$15 на июльском запуске, снижено на ~20% 30 июля (проверь актуальные) · выбор на каждый день

Большая часть реализации, когда направление уже зафиксировано. Изменения в нескольких файлах в чётких рамках. Free/Go часто попадают сюда.

Объём

Luna

API ~$1/$6 на июльском запуске, снижено на ~80% 30 июля (проверь актуальные) · быстро и дёшево

Шаблонный код, преобразования, массовые варианты, механическая полировка, рабочие сабагенты.

Привычки в Codex, которые всё ещё окупаются: AGENTS.md · маршрутизация по типу задачи (не всегда Sol) · Extra High только после проваленных проверок · Ultra только когда работа делится на части · циклы проверки · промпты в формате GitHub-issue (цель, пути, критерии готовности).

Для одностраничных сайтов брендов выигрывает любой, если разделять модели по фазам и проверять в браузере.

📌 От Бориса Черни, Anthropic и свежие советы практиков

Собрано из доклада Бориса на YC Startup School 2026 (на следующий день после Opus 5), его публичных тредов, документации Anthropic и самых содержательных постов в X/Reddit о работе над сайтами. Советы, которые относились только к более слабым моделям, оставлены за бортом.

✅ 1. Проверка — рычаг № 1 (качество в 2–3 раза выше)

Claude останавливается, когда работа выглядит готовой. Без проверки «прошло / не прошло» циклом проверки становишься ты. Дай ему то, что он может запустить сам.

Для сайтов: локальное превью, Chrome/DevTools, скриншоты ключевых брейкпоинтов, визуальное сравнение с референсом, Lighthouse, «не останавливайся, пока хиро не совпадёт с брифом на мобильном и десктопе». Пропиши критерии успеха прямо в промпте.

Борис (YC): проверка — это «пожалуй, самое важное, что люди делают неправильно».

🗑️ 2. Нажимай «удалить» примерно раз в 6 месяцев

Из доклада на YC, почти дословно: раз в полгода удаляй свой CLAUDE.md, скиллы и хуки. Посмотри, что модель делает без них. Возвращай только то, что по-прежнему регулярно ломается.

Anthropic сделала это у себя для Opus 5 / Fable 5 — абляция удалила ~80% системного промпта Claude Code без потерь в эвалах. Старые инструкции, написанные для слабых моделей, часто сковывают сильные.

Практичный размер: ~150–200 строк. Пиши только то, что Claude не может вывести из кода.

🔥 3. Задачи сложнее + промпты короче — дай ему поработать

Хватит промптов-приказов («сделай 1, потом 2, потом 3»). Опиши цель, ограничения и критерии готовности. Дай задачу чуть сложнее, чем кажется посильной, и отойди.

Пример Бориса с YC: задача на ~3 предложения, которая шла 14–15 дней — переписать Electron-приложение на Swift, запустить оба в виртуальной машине Mac, сделать скриншоты, сравнить попиксельно, не останавливаться, пока не готово.

Для сайтов: «Выпусти одностраничный сайт бренда, который совпадает с этим референсом на мобильном и десктопе; открой превью и итерируй, пока хиро и шкала шрифтов не совпадут». А не сценарий из 20 шагов.

🌳 4. Параллельные сессии / worktrees (по-прежнему главный прорыв)

Давний совет № 1 Бориса по продуктивности — и практики до сих пор его повторяют: 3–5 изолированных Claude (git worktrees или сессии в Desktop). Одно направление главной страницы, одна второстепенная страница, один адаптивный проход — у каждого чистый контекст.

claude --worktree feature-hero
claude --worktree page-about
claude --worktree responsive-pass

Одна цельная цель на сессию; не запихивай три клиентские задачи в один чат.

📝 5. CLAUDE.md как журнал ошибок + /init, потом урезать

После каждой правки: «Обнови CLAUDE.md, чтобы больше не совершать эту ошибку». Запусти /init для первого черновика, потом режь безжалостно. Вложенные файлы CLAUDE.md лучше одного гигантского в корне.

⚙️ 6. Скиллы / команды для всего, что делаешь каждый день

Если что-то случается чаще раза в день (проход по доступности, проверка OG, шкала шрифтов бренда, чек-лист деплоя), сделай из этого скилл или слеш-команду и закоммить. Сабагенты для исследования и проверки держат основное окно чистым.

🧹 7. Свежая сессия на каждую цельную задачу

Длинные запутанные треды деградируют. Паттерн, который постоянно всплывает в X/Reddit: одна цель → одна сессия → /clear или новая сессия, когда цель меняется. Посреди сессии используй /compact с указаниями, на чём сфокусироваться.

Снимать путы, а не добавлять инструкции. Продуктовый навес — это способности, которые у модели уже есть, но твоя настройка их не вытаскивает. Путы — это когда твои промпты и конфиг мешают. С моделями v5 ход по умолчанию — меньше костылей, задачи сложнее и цикл проверки, а не более толстый CLAUDE.md.

Что не превращать в карго-культ: «всегда начинай в plan mode» и «всегда используй самую сильную модель для всего» были вернее на старых моделях. Борис на сильных моделях сместился к большему авторежиму и меньшему обязательному планированию.

🧰 Полевые советы в духе Ника Сараева и других практиков

Устойчивые привычки из курсов Ника Сараева по Claude Code и от других практиков. Свежего мастер-класса Ника именно под Claude 5 нет — но эти вещи по-прежнему работают для сайтов и клиентской работы.

🗂️ 1. Разделяй клиентские и личные рабочие пространства

Правила бренда одного клиента не должны протекать к другому. Отдельные папки, сессии и локальные для проекта CLAUDE.md / CLAUDE.local.md. Правило агентства: одна сессия = одна цель клиента.

🌐 2. Проверка в браузере / DevTools по умолчанию для интерфейса

Для маркетинговых сайтов «тесты проходят» — недостаточно. Открой локальное превью, сделай скриншоты брейкпоинтов или гоняй Chrome/DevTools MCP, пока хиро, типографика и мобильная версия не совпадут с брифом. Вынеси этот цикл в скилл.

📎 3. Проверка живёт в скиллах, а не в толстом корневом файле памяти

Постепенное раскрытие: корневая память остаётся компактной (стек, подводные камни, указатели). Подробные шаги проверки, доступность, OG и правила шкалы бренда живут в скиллах, которые подгружаются по необходимости.

📖 4. Сначала документация для незнакомых API

Формы, аналитика, CMS, платежи: скажи агенту прочитать официальную документацию, прежде чем выдумывать код интеграции. Это срезает уверенное, но неправильное использование API.

🧾 5. Ошибки → в файл памяти; ежедневные воркфлоу → в скиллы

Тот же цикл, что и в пунктах 5–6 Бориса: постоянные правила — в память; всё, что повторяешь каждый день, становится скиллом — не объясняй бренд или шаги деплоя в чате заново.

⌨️ Claude Code Desktop — слеш-команды

Как это устроено: сначала команды с наибольшей отдачей, потом автономная работа (/goal, /loop), потом остальное. /plan — по ситуации (изменения во многих файлах / рискованные), а не обязательно для каждой задачи на сильных моделях. Переключение модели и уровня усилий живёт в интерфейсе Desktop, поэтому эти слеш-команды помечены «пропустить». Набери / в поле ввода, чтобы увидеть, что поддерживает твоя версия.

⭐ Наибольшая отдача (пользуйся этими)

/compact [instructions] Высокая ценность

Сжимает историю разговора и освобождает контекст, стараясь сохранить важное.

Когда: индикатор использования растёт (примерно 50–70%) или сразу после законченного куска работы, перед следующей фазой.

Почему это важно: в длинных сессиях на каждом шаге заново отправляется много истории. По-прежнему лучший способ работать эффективно в Desktop.

Совет: всегда давай указания, на чём сфокусироваться. Голый /compact работает хуже.

/compact сохрани текущий план, файлы, которые мы правили, и все нерешённые ошибки
/compact сфокусируйся на рефакторинге авторизации и оставшихся падающих тестах
/clear Высокая ценность

Начинает совершенно новый разговор. Предыдущий остаётся доступен в боковой панели сессий.

Когда: переходишь к совсем не связанной задаче.

Почему: несколько несвязанных задач в одной сессии сжигают токены и ухудшают качество.

/plan [description] Полезно

Включает plan mode (анализ без изменений) перед правками. Можно передать описание, чтобы сразу начать.

Когда: изменение во многих файлах, рефакторинг или всё, где сразу бросаться править рискованно.

/plan исправь баг авторизации, не меняя публичный API

🔁 Пусть Claude работает дальше (/goal или /loop)

Это два разных инструмента. Выбирай правильный.

/goal/loop
Следующий шаг начинается, когдаЗакончился предыдущий шагПрошёл заданный интервал
Останавливается, когдаУсловие выполнено (проверяет небольшая модель-оценщик)Ты его останавливаешь или Claude решает, что работа сделана
Лучше всего дляДовести дело до конца (тесты проходят, сборка успешна)Опрос / мониторинг (CI, деплой, комментарии в PR)
/goal [condition] Полезно

Задаёт условие завершения. Claude продолжает работать шаг за шагом, пока отдельная модель-оценщик не подтвердит, что условие выполнено. В сессии активна одна цель.

Когда: есть ясная проверяемая финишная черта и не хочется постоянно писать «продолжай».

Совет: сделай условие измеримым. Добавь лимит шагов, если нужен предохранитель.

/goal все тесты в test/auth проходят и линтер чистый
/goal npm test завершается с кодом 0 и git status чистый, или остановись через 15 шагов
/goal clear

Статус: набери /goal без аргумента, чтобы увидеть текущую цель, число шагов и потраченные токены.

/loop [interval] [prompt] Полезно

Повторяет промпт по расписанию, пока сессия открыта. Не укажешь интервал — Claude сам выберет темп.

Когда: периодические проверки (статус деплоя, CI, открытые PR), а не непрерывная работа до выполнения условия.

/loop 5m проверь, закончился ли деплой, и сообщи о сбоях
/loop 10m проверь мои открытые PR и разбери комментарии ревью
Важно: /loop работает на твоём компьютере, пока сессия открыта. Для долгой регулярной работы в Desktop есть «Запланированные задачи» в боковой панели.
/batch <instruction> По ситуации

Изучает кодовую базу, разбивает большое изменение на независимые части, а затем (после твоего одобрения) выполняет их параллельно в изолированных git worktrees.

Когда: большие рефакторинги или миграции, которые можно разделить. Для маленьких задач — перебор.

/batch перенеси оставшиеся компоненты из pages/ на новый app router

🔍 Ревью и откат

/code-review [level] [--fix]Полезно

Проверяет текущий дифф на баги и что можно почистить. С --fix может сразу применить правки.

Когда: перед тем как принять крупный набор изменений.

/diffПолезно

Показывает последние / незакоммиченные изменения и диффы по шагам.

/rewindПолезно

Откатывает разговор и/или код к более ранней точке.

Когда: Claude пошёл по плохому пути и нужна чистая отмена.

/branch · /fork · /resumeПо ситуации

/branch ответвляет разговор для экспериментов. /fork может отправить работу в фоновую сессию. /resume возвращает к прошлой сессии.

🧠 Настройка проекта и память

/initПолезно один раз

Создаёт стартовый CLAUDE.md, просканировав проект. Потом урежь его — держи коротким.

/memoryПо ситуации

Редактирование CLAUDE.md / файлов памяти. Лучше держать файл компактным.

/agentsПо ситуации

Создание и управление своими сабагентами (исследователь, тестировщик и т. д.).

🖥️ В основном есть в интерфейсе Desktop

/context · /usageОбычно не нужно

Подробная разбивка контекста или использование тарифа.

Альтернатива в Desktop: нажми на индикатор использования вверху сессии.
/btwОбычно не нужно

Побочный вопрос, не попадающий в основную историю.

Альтернатива в Desktop: Side Chat (⌘ + ; или Ctrl + ;).
/model · /effortПропустить

Переключить модель или уровень рассуждений.

Ты и так делаешь это в интерфейсе Desktop.

📦 Простой практичный набор

Всё перечисленное не нужно. Большинству пользователей Desktop хватит этого:

1. /compact с указаниями, когда растёт полоса использования

2. /clear (или новая сессия) при смене задачи

3. /plan перед крупными изменениями

4. /goal, когда есть ясная финишная черта

5. /loop, только когда нужны периодические проверки

Всё остальное — по желанию. Самая стабильная отдача по-прежнему у /compact.

Команды и их доступность могут меняться от версии к версии — набери / или /help, чтобы увидеть актуальный список.

✅ Что по-прежнему окупается в 2026

Это одни и те же принципы для Claude Code и Codex. Подробности — в разделах про Бориса и практиков выше; здесь — короткий общий чек-лист.

  • Циклы проверки — тесты, превью, скриншоты; агент останавливается, когда работа выглядит готовой, если ты не дашь ему проверку
  • Компактная память как журнал ошибок — CLAUDE.md / AGENTS.md только для подводных камней (~150–200 строк); процедуры → в скиллы
  • Результат + критерии готовности — цель и что значит «готово», а не списки шагов
  • Параллельная изоляция — worktrees / сессии / Ultra, только когда работа делится
  • Маршрутизация по фазам — модель для суждений → модель для объёма; повышай уровень только при проваленных проверках
  • Скиллы для ежедневных повторов — постепенное раскрытие вместо толстых системных промптов
  • Периодическое удаление — примерно раз в 6 месяцев выбрасывай конфиг, рассчитанный на слабые модели

🌫️ Что уходит / часто уже неактуально

Всегда брать самую сильную модель на максимальных усилиях

Было вернее, когда модели среднего уровня были слабыми. Сегодня это сжигает квоту, замедляет итерации и добавляет лишних раздумий над полировкой интерфейса. Повышай уровень по фактам.

Обязательный plan mode для каждой задачи

Критично для неоднозначной творческой работы; необязательно для «добавь этот компонент карточки». Борис публично сместился к большему авторежиму на сильных моделях.

Огромный CLAUDE.md / AGENTS.md как вики

Модели лучше справляются с суждениями сами; горы инструкций размывают сигнал. Оставь подводные камни; процедуры перенеси в скиллы.

Промпты по шагам «сделай 1, потом 2, потом 3»

Наследие слабых моделей. Лучше цель, ограничения, проверка. Пусть агент сам выбирает путь.

Фольклор промпт-инжиниринга как главный навык

Волны «промпт-инжиниринга» → «контекст-инжиниринга» быстро устаревают. Устойчивые навыки: сложные задачи, проектирование проверок, маршрутизация, вкус, оркестрация.

Одна бесконечная мегасессия

Гниение контекста — реальность. Свежая сессия на каждую цельную цель; по ходу — compact с указаниями.

🔄 Воркфлоу для сайтов, которые работают в обоих

Claude Code — сайты брендов и маркетинговые сайты

Направление: Opus 5 на high или Extra · 2–3 эстетических направления + информационная архитектура + критерии готовности.

Сборка: Sonnet 5 на high для секций, компонентов, мобильной версии.

Полировка: снова Opus, если согласованность или вкус всё ещё хромают.

Fable: только когда Opus всё ещё не справляется после сфокусированной попытки + compact.

Codex — та же работа, GPT-5.6

Направление: Sol Medium–High.

Сборка: Terra Medium (Luna для чистого объёма).

Жёсткий QA: Sol High + визуальные проверки.

Ultra: только когда страницы/компоненты — независимые потоки работы.

Общий паттерн (копируй)

1. Запиши критерии готовности (мобильный + десктоп, какие секции, ограничения бренда)
2. Модель для суждений планирует / предлагает направления
3. Одобри или сузь
4. Модель для объёма реализует
5. Проверь в браузере (скриншоты / превью) — а не «выглядит готовым»
6. Повышай модель или уровень усилий, только если проверка провалена
7. Записывай постоянные ошибки в CLAUDE.md / AGENTS.md

📅 Хронология и прогноз

2024 — начало 2025
Автодополнение → программирование в чате

Мастерство промптов значило очень много. Моделям нужны были жёсткие рамки и списки шагов. Появляется «вайб-кодинг».

Середина 2025 — начало 2026
Агентные инструменты для кода становятся мейнстримом

Claude Code и Codex взрослеют. Plan mode, файлы памяти, worktrees, долгие прогоны. Команды учатся проверке и параллельным сессиям.

Сейчас — середина/конец 2026
Модели по уровням + меньше строительных лесов

Claude 5 + GPT-5.6 Sol/Terra/Luna. Лаборатории удаляют большие куски системных промптов. Для хорошо описанной работы программирование «в основном решено»; узкое место смещается к вкусу, продуктовому суждению, оркестрации и доверию (ревью, безопасность, проверка).

Следующие 6–12 месяцев
Дольше автономность + мультиагентность по умолчанию

Прогноз по направлению: многодневные прогоны станут обычнее; мультиагентность — более встроенной; циклы IDE/облака — плотнее. Конфиг, написанный для слабых моделей, будет и дальше гнить — планируй удаления.

12–24 месяца
Роль оркестратора закрепляется

Вероятное преимущество: формулировать результаты, проектировать проверку, распределять задачи между парками агентов, держать планку качества и отвечать за продуктовые и брендовые решения, с которыми модели пока справляются плохо. Считай это ставкой, а не гарантией.

🧠 Какие навыки развивать (и какие отодвинуть)

Вкладывайся сюда

  • Спецификация и критерии приёмки — ясное «готово»
  • Проектирование проверок — тесты, визуальные проверки, циклы в браузере
  • Маршрутизация моделей — уровень и усилия по типу задачи
  • Оркестрация — параллельные сессии, скиллы, долгие цели
  • Вкус и чувство бренда — особенно для клиентских сайтов
  • Читаемость репозитория для агентов — компактные файлы памяти, хорошая структура
  • Дисциплина ревью — та же планка для кода ИИ, что и для человеческого
  • Гигиена конфига — периодически удалять и собирать заново

Отодвинь на второй план

  • Заучивать хрупкие шаблоны промптов
  • Копить всё более длинные системные промпты
  • Набирать каждую строку руками «чтобы не терять форму» как главный навык
  • Трайбализм инструментов (только Claude / только Codex)
  • Считать, что прошлогодние лучшие практики работают и после скачка фронтира

Для сайтов и агентской работы особенно: делай ставку на визуальную проверку, изоляцию клиентов, токены дизайн-системы как источник истины и маршрутизацию по фазам (модель для суждений → модель для объёма). Именно там живут качество и маржа.
